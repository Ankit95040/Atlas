# M27.6 — Execution Topology Feasibility Audit

Status: **READ-ONLY AUDIT — no implementation**. All references are to the
M27.5 working tree. The generated reference image is treated as conceptual
direction, not specification; every feasibility claim below is grounded in
inspected source, schema, or API contract.

## 1. Executive recommendation

**Concept A (execution topology) is feasible with current data; Concept B
(zones) is not, and must stay a borrowed accent at most.** The deciding
factor is data, not taste: Atlas persists tasks, dependency edges, worker
assignments, verification verdicts, and merge commits — i.e. a DAG with
attachments. It persists no zone assignments, no facility coordinates, no
phase-location mapping. Zones would therefore be either arbitrary
decoration or a new domain concept smuggled in through visuals — both
forbidden. The honest reading of Concept B that survives is small: the
gate row and railyard are already linear "zones" along +z; keep them as
bands, do not build a facility.

Second, the single biggest blocker to *any* topology — A or otherwise —
is not geometry but **camera reset**: `update()` re-sets camera position
and controls target on every poll (`client.ts:792-795`), so any user orbit
is destroyed every 2.5s. Topology work must start with refit-only-on-
bounds-change, before any new geometry lands. This is a ~15-line change
with a large UX payoff and is proposed as Phase 0.

Third, the reference over-labels (every T1–T5 chip is permanent) and
invents data (Type, Logs, durations, worker %). The audit retains M27.5's
anomaly-first labels and bans those four fabrications explicitly (§3).

## 2. Current architecture findings

- **Pipeline** (unchanged since M25, verified): `loadWorkflow` →
  `WorkflowGraphData` → `buildIslandScene` (pure, deterministic) →
  `/api/run/:id/island` → `createIslandRenderer.update()` full rebuild +
  `play()` priority-ordered transitions. Scene is always final when idle;
  reduced-motion snaps everything.
- **Descriptor richness (verified in `scene.ts`)**: buildings carry
  `taskId/title/status/level/col/x/z/wave/verdict/integrated/dependsOn/
  worker{id,status,link}`; paths carry `fromTaskId/toTaskId/satisfied`;
  gates carry `taskId/title/verdict/reasons`; cars carry
  `taskId/title/sha/subject/order`; plus `halt`, `harbor.branch`,
  `phases[{name,active}]`, `waves[{n,titles}]`, `bounds`, `seed`.
  `level` is verified longest-path dependency depth (`layoutLevels`,
  `views.ts:504`); `wave` is the 1-based scheduler wave, nullable.
- **Workspace payload** (`api.ts` + `serve.ts:296`): summary counts,
  tasks (`dependsOn/requiredBy/claims/worker/testRuns{status,exitCode}/
  verdict/reasons` — **no wave, no level, no timestamps, no
  description**), workers (**no timestamps**), verification findings,
  train branches, events **with `createdAt`**.
- **Renderer state (M27.5)**: status-mass bodies, hollow COMPLETED_EMPTY,
  FAILED/BLOCKED base rings, worker color-by-status + opacity-by-link,
  neutral rails (satisfied ink / unsatisfied raised pale), failed-only
  gate labels, unlabeled cars, neutral harbor lamp, ground plate + level
  bands, hover chip (one reusable sprite), selection ring + selection
  label, `focus()`/`resetView()` with reduced-motion snap, keyboard
  (Esc / `[` `]` cycle / `F` focus, input-guarded), Focus/Reset overlay
  buttons, full disposal incl. LineSegments.
- **Interaction/selection**: raycast picking with 6px drag threshold,
  cursor-only hover, click → `onPick` → workspace `Selection`
  (`task|worker`) → panel detail + 3D outline. Camera never moves on
  selection (human-approved). SSR boot passes no opts → legacy route
  navigation preserved; `view.ts` needs no changes for any proposed work
  except inheriting it.
- **Accessibility today**: canvas `aria-label` + `role=status` live
  summary line; Tasks lens list is a full keyboard twin (filter, select,
  arrow-navigable buttons); skip link, `aria-current`, visible focus,
  reduced-motion CSS + projector snap. No 3D-only information exists:
  every entity is reachable in a lens list. This parity is the floor —
  topology phases must not regress it.

## 4. Spatial model

- **Keep dependency-depth layout.** `level` (longest-path depth) on z,
  column index on x is already the topology Concept A asks for; M27.5
  bands make it readable. Do not adopt force-directed or radial layouts:
  they are unstable across polls (positions must be a pure function of
  `(level, col)` or selection/identity breaks every 2.5s), and they hide
  the scheduler's own wave/level semantics.
- **Sequential vs parallel**: chains serialize along z (verified in
  structure tests); parallel tasks share a level row — correct and
  already covered by `ui-island-structure.test.ts`.
- **Cycles / missing deps**: `layoutLevels` breaks cycles at depth 0 and
  ignores edges to unknown ids; `scene.ts` skips paths with unknown
  endpoints. Keep both guards; add a test for a cyclic synthetic graph
  (currently untested — Phase 1).
- **Stability rule (new, normative)**: layout is a pure function of
  `(level, col, bounds)`; entity world-positions for identical descriptors
  must be bit-identical across polls. The current builder satisfies this
  (deterministic sort + no randomness since M27.5 removed the wobble);
  lock it with a determinism test (exists for 25 tasks — extend to
  include positions, not just JSON equality).
- **Large-DAG readability**: rows compress (fixed 7-unit pitch is fine to
  ~15 levels; beyond that fit-zoom shrinks everything — the failure mode
  is illegibility, handled by §6 budgets, not by layout cleverness).

## 5. Visual system (delta from M27.5, not a restart)

- **Nodes**: keep status masses; add thin top-edge cap in status color at
  higher emissive for active states (one extra box per building, shared
  geometry) so state reads from directly above (current top-down view is
  the weakest angle). **Differs from M27.5**: color moves from whole-body
  wash to body + luminous cap; bodies desaturate one step toward graphite
  so the cap carries the signal.
- **Edges**: satisfied = current ink rails; blocked-dependent edges =
  dashed pale lines (`LineDashedMaterial`, computed distances); direction
  cones stay, neutral steel. Blue never touches an edge.
- **Workers**: keep attached color/opacity units; add a 1-unit mast +
  lamp on RUNNING units only, so "running" reads at distance without a
  label.
- **Verification/merge**: keep gate row + railyard; add in-progress
  amber frames (derived, §3); add a low slab under the yard (grouping,
  not new data); keep halt beacon + harbor as-is.
- **Status colors**: unchanged palette (spec §5 as implemented); fix the
  one inconsistency found in audit: CSS `ok` is `#3fb950` while the lamp
  `COMPLETED` emissive is `0x2ea043` — unify on `#3fb950` family.
- **Lighting/contrast**: cooler key light (current warm cast fights the
  graphite system); keep fog + shadows; matte ground stays.
- **Labels**: anomaly-first stands (reference's permanent T-chips are
  rejected for density). Hover chip + selection label stand. Cap: no
  full-label mode above 40 buildings; zoom capping (fade beyond distance)
  is the one label improvement proposed.
- **Camera/focus**: fix the reset defect (§1) first; keep ortho, fit math,
  `focus()`/`resetView()`, keyboard map. Add Top-view toggle only (a
  second preset beside home; Perspective toggle rejected — ortho is the
  instrument look and avoids game aesthetics).

## 6. Performance strategy (measurable budgets)

Per-task object cost today: body + roof + lamp + (rings/edges/labels
conditional) + worker unit + ~2 rail meshes per edge. Budgets (objects in
`world`, measured via existing `describe()`):

| Tasks | Edges (assumed) | Object budget | Labels | Motion | Target |
|---|---|---|---|---|---|
| 20 | ~25 | ≤ 250 | anomaly + hover | full diff-player | orbit ≥ 30fps on integrated GPU |
| 100 | ~130 | ≤ 1,100 | anomaly-only, no gate-passed labels | diff-player, skip car-slide beyond 60 cars | orbit ≥ 30fps discrete GPU; degraded-but-usable integrated |
| 200 | ~260 | ≤ 2,200 | anomaly-only, hover throttled to 150ms | state-change pulse only (no car-slide, no gate tween) | discrete GPU ≥ 30fps; integrated falls back to list-first UX with 3D still correct |

- Measure with `describe()` object counts + `performance.now()` around
  `update()` in Playwright (new perf spec, desktop Chrome, system
  browser already used). No 100/200 claims without these numbers.
- If budgets miss: share geometries already (sharedBox); next levers are
  sprite-atlas labels (one texture, many quads) and merged-geometry
  rails — both Phase 4+, only on measured failure.
- Reduced motion: unchanged (snap everything; transitions already skip).

## 7. Accessibility strategy

- Keep the Tasks lens as the complete twin: every topology addition
  (dashed edges, in-progress gates, mast lamps, minimap regions) must
  have a list/badge equivalent. Minimap is `aria-hidden` with a
  "jump to level" listbox alternative.
- SR summary line extended with counts by state (already a live region).
- Keyboard map extends: `T` top view, `M` focus minimap list, existing
  Esc/`[`/`]`/`F` unchanged. Document in-app (one line in the viewport
  footer, not a modal).
- Contrast: emissive caps checked against ground at 3:1 minimum for
  large-area state; text chips unchanged (dark chip + ink-100).

## 9. Risks and unresolved decisions

1. Camera-reset fix changes SSR boot framing behavior too (shared
   `update()`) — verify `mode=3d` SSR snapshot tests after Phase 0.
2. Emissive caps + shadows may blow out on low-end GPUs — screenshot
   gate on the reference machine, not just CI.
3. Dashed lines + fog + ortho can shimmer; if so, drop dashes for
   raised-pale-solid (fallback recorded here, not improvised later).
4. Minimap duplicates the Tasks lens; if user testing shows zero use,
   cut it — it is the cheapest phase to abandon.
5. Unresolved: whether `focus()` should also switch the panel lens to
   Tasks (currently selection only pins the card) — needs human call.

## 10. Explicit non-goals

No zones-as-geometry, no full-time labels, no worker progress, no task
types, no Logs tab, no time estimates, no perspective mode, no second
WebGL pass, no API fields for wave grouping, no inline mutations, no SSR
removal, no engine/scheduler/DB changes, no 100/200-task performance
claims without measurement.
