# M27.4 — Island Visual Redesign: Design Specification

Status: **SPECIFICATION ONLY — no implementation**. All file/line references
are to the M27.3 working tree. Nothing outside this document is created or

## 1. Current-state audit

### 1.1 Rendering architecture (verified in source)

- **Pipeline**: `loadWorkflow(db)` → `WorkflowGraphData` (`src/ui/data.ts:754`)
  → `buildIslandScene()` (`src/ui/island3d/scene.ts:78`, pure, deterministic)
  → `IslandScene` JSON over `/api/run/:id/island` → `createIslandRenderer`
  (`src/ui/island3d/client.ts:103`) → `update()` full rebuild + `play()`
  sequential transitions (`transitions.ts`, 200–600ms, priority-ordered,
  first-render emits nothing). React polls island 2.5s, workspace 5s
  (`IslandCanvas.tsx`, `Workspace.tsx:22`).
- **Camera**: orthographic, position (34,34,34), refit to `bounds` on every
  `update()` (client.ts:559-567); OrbitControls, damping off, pan on,
  zoom 0.4–4, polar clamp. Render-on-demand (no loop).
- **Picking**: raycast against `world.children`, 6px drag threshold
  distinguishes orbit from click; hover changes cursor only. Click either
  navigates to SSR routes (`routeFor`, client.ts:151) or reports
  `IslandPick` via `onPick` (React). Selection = accent ring
  (`selectionRing`, re-resolved after every rebuild). No camera motion on
  selection anywhere.
- **Lighting/materials**: warm directional sun + cool hemisphere, PCFSoft
  shadows, graphite background `#0a121c`, fog 90–220, pixelRatio ≤ 2.
- **Enforced discipline** (`tests/ui-island3d.test.ts`): projector does no
  fetch, no writes, no orchestration; transitions pure/deterministic;
  importmap-resolved vendor files only.

### 1.2 Domain objects → current visuals (the problem inventory)

| Domain (source) | Current visual | Defect |
|---|---|---|
| Task status (`buildings[].status`) | Identical gray concrete boxes; status only in lamp emissive + text label | Execution state unreadable at a glance; colorblind-hostile (hue in one small sphere) |
| Dependency depth (`level`, `ROW_GAP`) | Z-row placement + pads | Reads as parking rows, not flow; direction ambiguous despite cones |
| Dependency edge (`paths[]`, `satisfied`) | Blue vs translucent-gray rails | Satisfied=blue collides with live-worker blue; no blocked/failed edge state |
| Worker (`worker{id,status,link}`) | Small gray box beside building | Live vs historical distinguished by opacity only; worker *status* (RUNNING vs FAILED) invisible |
| Verification (`gates[]`, verdict) | Pillar pair + beam, ✓/× label | Only tasks *with* verdicts get gates; unevaluated work has no gate presence; reasons only in panel |
| Merge (`cars[]`, sha/subject/order) | Dark-green boxes on rails | Green collides with COMPLETED green; order shown only by x-position |
| Halt (`halt.reason`) | Red octahedron + label | Present; keep |
| Harbor (`harbor.branch`) | Pier + amber lamp + label | Present; keep, de-emphasize lamp (amber also means verification) |
| Tower | Shaft + deck + red beacon | **Pure decoration, controls nothing** — remove |
| Terrain | Seeded irregular disc + water + fog | Arbitrary; communicates nothing about topology; wastes frame on water |
| Labels | Permanent sprite per building AND per worker (`title · STATUS`) | Structural overlap; fixed world-size text; the rejected look |

### 1.3 Data actually available (no new loaders needed)

- Per task: `status`, `wave` (1-based, nullable), `verdict`, `reasons[]`,
  `integrated`, `dependsOn[]`, `worker{id,status,link}` (scene descriptor);
  plus via workspace payload: `requiredBy[]`, `claims[]`,
  `testRuns[{status,exitCode}]` (`ApiTaskSchema`, api.ts:49).
- Sequence position: derivable client-side by joining `ApiTask.id` to
  `IslandScene.buildings[]` (`level`, `col`) — **no API change required**.
- Run scope: `runStatus`, `phases[{name,active}]`, `waves[{n,titles}]`,
  `trainHalted/HaltReason`, `trainCars`, `defaultBranch`.
- Workspace summary counts + `haltReason`; events with `createdAt` (can
  derive recency, never shown as fake progress).
- **Not available, must not be rendered**: task progress %, worker
  utilization, log streams, artifact contents, time estimates, priority
  scores, wave readiness beyond `schedulePreview` (not currently exposed).

## 2. Design principles

1. **Topology over terrain.** Space encodes dependency depth (x) and
   sequence (z). Every geometric element must map to §4 or be deleted.
2. **Status is mass first, light second, text last.** A red task reads red
   at 10% zoom with all labels off.
3. **Blue is reserved**: live workers, selection, actionable controls.
   Nothing else emits blue — including satisfied-dependency rails.
4. **Stillness is the default.** Motion only on polled state change via
   the existing diff-player. Camera never moves unless the operator moves
   it (add explicit Reset/Top/Perspective controls instead).
5. **Honesty at every zoom.** No invented aggregation: dimming and label
   capping hide detail, never summarize falsely.
