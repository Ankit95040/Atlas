## 1. Phase A — workspace safety guard
Incident (M28.3 profiling): defaults resolved `workspaceRoot`/`trainPath`
under `process.cwd()`, and a harness run from the Atlas checkout created
`.atlas/work/` inside it (empty dirs only; verified no commit, branch,
or registered worktree resulted; removed).

Fix (`src/cli/run-command.ts`, single choke point — the only
cwd-default in the codebase): `resolveWorkspaceRoot()` honors explicit
`--workspace-root` verbatim (dogfooding stays possible) and refuses the
silent default when it lands inside the positively identified Atlas
checkout (`package.json` name `atlas` + `prisma/schema.prisma` from the
binary's own path; unidentifiable layouts degrade to no-op). Refusal
names the escape hatches and guarantees nothing was created.
`tests/workspace-safety.test.ts` (6/6): explicit-inside-checkout
allowed, silent-default refused (incl. subdirs), external repos and
tmpdirs pass, non-git paths still fall through to repository validation.

Proven live against the real binary: refusal emitted, `.atlas/`
absent, worktree list unchanged. (First attempt silently used a stale
`dist` — caught by the same verification; rebuilt and re-proven.)

## 3. Phase C — conclusion: documented no-op
Every remaining list/HEAD read is a security gate, sits across an
external-mutation window (provider, test scripts, prior train items),
or is a before/after pair by design. Consolidation would thread values
across trust boundaries the code deliberately re-checks (workspace
confinement, train integrity). The M28.3 root memo stands as the safe
win; no read caching added. `createWorktree`'s double parse is
intentional (commented: Git assigns the branch).
