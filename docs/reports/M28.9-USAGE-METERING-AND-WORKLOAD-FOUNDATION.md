## 3. Provider event findings (observed, not assumed)
- `opencode run --format json` emits one `step_finish` event per model
  step; multi-step sessions emit several. Verified live: totals, input,
  output, reasoning, cache read/write, and cost all present on the free
  tier (cost `0`).
- One invocation ≠ one event: aggregation SUMS across events (never
  overwrites); identical duplicates sum deterministically.
- Usage becomes available in the Atlas parent when the child exits
  (captured stdout), i.e. post-invocation — never streaming, never
  mid-execution. Mapping to task/run is by construction (the
  `execute()` call owns taskId/workerId).

## 4. Usage schema and persistence changes
- `src/workers/usage.ts` (new, pure): `ProviderUsageSchema`,
  `extractProviderUsage()`, `aggregateUsage()`.
- `ProviderOutputSchema` += optional `usage` (additive; strictness
  preserved; existing outputs validate unchanged).
- `CommandWorkerProvider.execute()` attaches Atlas-parsed usage (our own
  observation of child bytes, same trust level as `notes`).
- `runtime.ts` persists one `PROVIDER_USAGE_OBSERVED` event per parsed
  return (featureId/taskId/actor `atlas-metering`), inside a
  failure-isolated helper: persistence errors cannot fail tasks.
- New `EventType` value only; SQLite materializes no enum SQL, so no
  migration file is required (`prisma generate` re-ran clean).
- Benchmark `buildRealRunResult` fills `usage` from per-task rows;
  `usageRecordSchema.tokens` evolved from scalar to the nullable
  breakdown object (only consumer was the null-asserting test, updated
  by behavior, still null-safe).

## 5. Null and zero semantics
Missing → null at every layer (no event, unparseable, absent
dimension). Observed zero stays zero (free-tier `cost: 0` preserved and
tested). Totals are sums only under complete coverage, else null with
the gap named. No estimation, no zero-filling, no price inference.

## 6. Duplicate/multiple-event behavior
Multiple well-formed rows per task sum deterministically (taskId,
event-id order); malformed rows poison only their own task to null;
identical duplicates sum (documented, tested). No double-counting:
exactly one record path per invocation (throw paths record nothing).
