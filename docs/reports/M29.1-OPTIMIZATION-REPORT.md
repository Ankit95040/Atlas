# M29.1 — Optimization Report: Test-Hygiene Query Skip

Status: **IMPLEMENTED, uncommitted**. One isolated change with a
deterministic benefit proof. No semantic, retry, security, or merge
change. Full-gate result in §5.

## 1. Bottleneck selected (Phase 0/A evidence)
A logging-`git` shim over a 1-task run counted 57 spawns; no further
git consolidation is safe (M28.4: every remaining list/HEAD read is a
confinement gate, an external-mutation window, or a before/after pair
by design). Re-examined candidates and rejected with evidence:
- Train per-item `verifyExecution`: cites existing `testRunId`, does
  NOT re-run tests — no redundancy.
- `getWorktreeChanges` twice per task (execute + verify): test scripts
  run between them and may write files — second diff required.
- Scheduler reloads: 0–2ms/round, closed.
- Approvals/events writes: single-digit ms, required records.
- Selected: `trackTaskEvidence` runs 4 indexed `findMany` per task even
  when the tracker is the production noop (results discarded). Pure
  waste, statically verifiable, zero correct-readers depend on it.

## 2. Implementation (Phase B/C)
`src/orchestrator/run-loop.ts` only (+13/−9 lines):
- `track` stays optional end-to-end (`deps.track` used directly instead
  of defaulting to a noop; `runOneTask` and `trackTaskEvidence` accept
  `undefined`).
- `trackTaskEvidence` returns before any query when untracked; all 12
  `track(` call sites use `?.`.
- No behavior change by construction: previously a noop consumed the
  identical results.

## 4. Before/after measurements (Phase D, M28.2 methodology)
- Query counts (deterministic): 4 evidence queries/task with tracker,
  **0 without** — proven by test, not inferred.
- Wall clock, same harness: 1-task 1284ms (M28.3: 1279), 3-parallel
  2925ms (2917), 3-chain 2951ms (2931) — all within ±1% machine noise.
- Verdict: **accepted on structural grounds** (dead queries eliminated,
  parity proven, zero risk surface). Wall-clock benefit is below the
  noise floor on ≤3-task shapes and is reported as such — no speedup
  claimed. The benefit scales with task count and DB size (4 queries ×
  tasks, each a full round-trip the database no longer serves).
