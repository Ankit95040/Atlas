# M28.3 — Optimization Report: Repository-Root Memoization

Status: **IMPLEMENTED, uncommitted**. One isolated change, measured
before/after with the M28.2 methodology. Full-gate result in §6.

## 1. Bottleneck selected
Per-task git subprocess audit via a logging `git` shim on a 1-task run:
**57 spawns, of which 25× `rev-parse --show-toplevel`**, 8× `worktree
list`, 8× `rev-parse HEAD`. Root resolution re-ran in `executeTask`,
`verifyExecution`, `getWorktreeChanges`, and the train for identical
paths. Measured: `toplevel` median 8–19ms depending on repo → ~25 calls
≈ 200–475ms, roughly a third of the 1-task Atlas overhead.

## 2. Implementation
`src/git/repository.ts`: process-lifetime memo of `getRepositoryRoot`
keyed by input path, successes only. Failure paths re-execute every
time, so `NotGitRepositoryError` semantics are unchanged (proven by a
new test: fail-then-init-then-succeed on the same path). Concurrent
waves share the in-flight promise. HEAD, diff, and worktree-list reads
stay live deliberately — agents and the train mutate those between
reads (worktree-list caching was evaluated and rejected: it would weaken
the workspace-confinement gate if an agent manipulates worktrees).
No semantics, retry, security, or merge change; one file, +18 lines.

Correctness risk accepted and bounded: a repository moved or deleted
mid-process keeps serving its last good root for that path. Runs last
minutes and never relocate repos; tests use unique tmpdirs per case.
Full suite run to prove no test depends on re-resolution.

## 7. Remaining bottlenecks (measured, next in line)
1. `worktree list` ×8 + `rev-parse HEAD` ×8 per task (~16 spawns,
   ~300ms): needs freshness-safe design (invalidation around provider
   execution + train mutations) — M28.4 candidate, NOT done here.
2. Worker spawn+exec ~265ms for trivial stubs: Node startup floor;
   keep-alive agents rejected (breaks process-group isolation).
3. Test-suite and provider latency: external, dominate production.
