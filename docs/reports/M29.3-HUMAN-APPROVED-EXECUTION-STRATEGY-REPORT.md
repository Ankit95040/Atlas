# M29.3 — Human-Approved Execution Strategy Report

Status: **IMPLEMENTED (contract only), uncommitted**. No execution,
scheduler, retry, merge, or recovery change. Full-gate result in §7.

## 1. Architecture audit (Phase 0)
- Production executes exactly one path: the orchestrated wave loop for
  every plan shape. A single-agent route exists only in the benchmark
  harness (`runRealSingleAgent`: union task through identical gates).
- Production providers receive bare argv (no prompt concept); task
  content reaches agents via workspace state. Strategy therefore lives
  entirely in **plan shape** (1 vs N tasks), decided at plan-approval
  time — not in execution mechanics.
- Invariants identical across strategies by construction: claims,
  workspaces, provider invocation, verification, failure
  classification, recovery eligibility, events, train gates, final
  run-state. A union-task plan changes none of them.
- Consequence: no new execution path is needed or built. The missing
  piece was the approval contract — recommended vs actual vs approval —
  which is what this milestone implements.

## 2. Approval contract (Phase 1)
- **Recommended**: `recommendRoute` (pure, deterministic, stable rule
  IDs) computed at `plan` time over validated tasks/deps/claims and at
  `run` time over persisted rows; recorded in both outputs.
- **Actual**: derived, never flagged — `deriveActualStrategy(n)`:
  single persisted task → SINGLE_AGENT (coordination impossible),
  otherwise ORCHESTRATED. Describes the approved plan's shape.
- **Approval state/timestamp/actor**: the existing plan approval row
  (decidedAt/status/actor), referenced by ID in both outputs. No new
  approval system: approving a shape that diverges from the
  recommendation IS the auditable override (recommendation + actor +
  timestamp + actual all recorded separately).
- **Override reason**: covered by divergence itself; no new required
  field was added (new approval UX friction was rejected as scope
  creep — recorded here as an explicit non-requirement).
- **Fail-closed**: unknown shapes, unloadable inputs, and any future
  unimplemented strategy resolve to ORCHESTRATED/REQUIRES_REVIEW, i.e.
  existing safe behavior. No `--strategy` flag was added: with
  identical execution mechanics it would be vacuous UI, and implicit
  approval via CLI defaults is explicitly forbidden.

classification, recovery eligibility, events, train gates, final
run-state semantics, human review — zero diffs in all owning files.

## 8. Known limitations
- `actualRoute` derives from persisted task count, not from observed
  coordination (a 1-task run that internally retries still reads
  SINGLE_AGENT — correct per definition, documented).
- Override reasons are implicit in divergence, not a required field.
- A future executable `--strategy` flag remains a product decision,
  not a technical gap.

## 9. Explicit adoption decision
Contract ADOPTED (record-only, zero execution impact). Execution
routing stays unified: no alternate path exists to enable, so there is
nothing to gate. Any future executable strategy selection requires its
own milestone with the same contract extended, not a silent extension
of this one.
