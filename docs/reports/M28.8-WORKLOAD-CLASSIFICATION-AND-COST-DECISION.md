## 3. Workload classes (max five, operationally defined)
1. **Independent units** (exists: login+billing). No shared files;
   union claims partition cleanly; integration is ordering-only.
   Parallel workers structurally useful; single agent sufficient when
   total context fits comfortably. Route on context fit + wave count,
   not task count.
2. **Sequential chains** (exists: schema→validator). Later tasks consume
   earlier artifacts; depth ≥2 forces Atlas waves or single-agent
   discipline. Parallelism structurally useless within the chain.
3. **Shared-interface** (to author): tasks editing one contract plus its
   consumers. Contention is semantic (import shapes, type changes),
   not file-exclusive. Expect CONFLICT halts and rework. Parallelism
   useful with verified-contract-first ordering; single agent risks
   silent interface drift across a long context.
4. **Integration-heavy** (to author): claim-disjoint but semantically
   coupled changes. Primary signal is the integration-failure rate,
   not latency. Atlas justified iff the train catches real conflicts
   the single agent merges blindly.
5. **Schema/migration** (to author): data-model change with elevated
   verification (multi-file assertions, migration order). Highest
   verification cost; single agent acceptable only with a strong
   suite; Atlas justified by isolated verification per migration step.
No class is labeled easy/hard/ideal. Each carries a falsifiable
expectation above.

## 4. Routing framework (checklist, human-approved)
Route SINGLE iff: one work unit OR union context fits with margin AND
no ordering constraints AND suite runs in one shot. Route ATLAS
SEQUENTIAL iff: dependency depth ≥2 with artifact handoff. Route
ATLAS PARALLEL iff: ≥2 claim-disjoint units AND union context strains
the model AND integration is ordering-only. REJECT the decomposition
(ask for better spec) iff: claims overlap on WRITE without stated
ownership, acceptance criteria untestable, or no suite exists to
verify against. Signals evaluated qualitatively; numeric thresholds
(e.g., context-fit margin, depth cutoffs) are marked NEEDING
CALIBRATION — no invented cutoffs. Human approval stays mandatory;
no silent routing.

## 6. Evaluation design (falsifiable, screening)
Arms A (single) / B (Atlas) as M28.6; stub arm only for overhead
questions. Classes 1–2 existing; 3–5 require authored fixtures first.
n=5 screening (label it), n=10 for the two cheapest cells on spread.
Matched prompts/snapshot/provider/timeout/suite/predicate; pristine
asserts; randomized arm order (M28.6 fixed-order limitation explicitly
fixed here by requiring shuffle); paired trials share fixture snapshots.
Success = completed+verified+non-empty+integrated. Measures: quality,
e2e + critical-path latency, calls + parsed tokens, cost-or-null,
integration failures, rework, interventions. Falsification targets:
"If Atlas overhead exceeds single-agent wall on class 1 at n=10,
parallel orchestration is not justified there" (and per-class analogs).
