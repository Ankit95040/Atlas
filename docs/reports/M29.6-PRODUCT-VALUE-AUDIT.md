## 3. Concrete workflow analysis
Five M28.8 classes map to these user problems:
1. **Bounded multi-module feature** (login + billing, disjoint files):
   user wants two small modules built and tested. Single agent is
   sufficient in principle; Atlas adds scheduling + ordered integration
   + per-module verification trail.
2. **Shared-interface refactor** (two tasks, one settings file): user
   wants two disjoint edits to one file without clobbering. Single
   agent serializes naturally; Atlas parallelizes then collides.
3. **Migration with ordering risk** (schema → validator/reader chain):
   user wants ordered, verified steps. Single agent must self-discipline
   ordering; Atlas enforces it structurally.
4. **Bug fix with regression risk**: user wants a fix plus proof
   nothing else broke. Atlas's Atlas-executed test gate is the value;
   decomposition adds little for a one-line fix.
5. **Overlapping-file change**: user wants two edits to one file
   merged safely. Neither arm has solved this yet (UNMEASURED for real
   providers; stub-only evidence of clean disjoint merge).
Each requires human approval at plan and merge; objective success is
the shared predicate (completed + verified + non-empty + integrated).

## 6. Product-position recommendation: **B, narrowed**
**B. Safety-first execution control plane for coding agents** — with
the explicit narrowing: Atlas is currently a control plane for
*audited, recoverable, integration-gated* agent execution, proven
only on small synthetic workloads. It is NOT (A) a general
orchestrator (no evidence it helps broadly; single agent is faster
everywhere measured), NOT (C) specialized yet (no class shows a
positive Atlas-only outcome), and NOT (D) merely an experiment harness
(the CLI + guards are a real, coherent product surface).
- Pain it addresses: unverifiable agent output, clobbered parallel
  edits, unrecoverable stuck runs, unowned merges. Real pains, but
  unvalidated against paying-user demand — no customer evidence exists.
- Substitutes: single strong agent + `git` discipline (faster today);
  CI pipelines (better regression story); human code review (better
  judgment). Atlas's edge is *combined* enforcement in one loop, which
  no substitute currently offers.
- Deliberately NOT: auto-routing (disabled, stays disabled), broad
  task classes, dashboard rebuilding, prompt engineering, model
  selection.

## 7. Competitive substitutes and differentiation
Covered in §6. The durable differentiator, if any, is the
evidence trail: every state change is an append-only event with an
actor, every merge is gated on Atlas-executed tests, every stuck
assignment has an explicit recovery path. That is a compliance-grade
property single-agent workflows structurally lack. Whether anyone
pays for it is UNKNOWN.
